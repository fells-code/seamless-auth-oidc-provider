# OAuth 2.1 and RFC 9700 matrix

How the provider meets the OAuth 2.1 draft and RFC 9700 (OAuth 2.0 Security Best Current
Practice). "Edge" is this service's locked `oidc-provider` configuration, which no client
setting can loosen. "Registry" is the API's application management
(`/admin/applications`), which refuses a configuration that would be insecure before it is
stored. Each row names the test that holds it.

| Requirement                                                    | Where    | How                                                                                                                                                                               | Test                                   |
| -------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| PKCE for every client, `S256` only (9700 2.1.1)                | Edge     | `pkce.required` always true; discovery lists only `S256`; `plain` is refused                                                                                                      | `oauth21.test.ts`, `authorizationCode` |
| No implicit or hybrid flow (9700 2.1.2)                        | Edge     | `responseTypes: ['code']`; `token`, `id_token` and `code id_token` are refused                                                                                                    | `oauth21.test.ts`                      |
| No resource owner password grant (9700 2.4)                    | Edge     | Not implemented by the library; answered `unsupported_grant_type`                                                                                                                 | `oauth21.test.ts`                      |
| Exact redirect URI matching (9700 2.1, 4.1.3)                  | Edge     | Exact string match. The only exception is the port of a native client's loopback redirect                                                                                         | `oauth21.test.ts`                      |
| Redirect URIs that can be registered                           | Registry | `https` (not `localhost`), `http` on `127.0.0.1` or `[::1]` only, or a reverse-domain private-use scheme; no fragments or credentials                                             | API and types tests                    |
| Native apps (RFC 8252 7.1 to 7.3, 8.3)                         | Both     | Loopback redirects match on any port with the same host, path and scheme; `localhost` is refused; private-use schemes and claimed `https` links match exactly                     | `oauth21.test.ts`                      |
| Public clients cannot hold a secret                            | Registry | A public client uses `none` and PKCE, and cannot use `client_credentials`                                                                                                         | API and types tests                    |
| Refresh token rotation or sender constraint (9700 2.2.2, 4.14) | Edge     | `rotateRefreshToken: true`; a reused refresh token revokes the grant and ends the first-party session                                                                             | `refreshAndClientCredentials.test.ts`  |
| Authorization code single use, revoke on reuse (9700 4.2.4)    | Edge     | The library consumes the code; a second redemption revokes what the first issued                                                                                                  | `oauth21.test.ts`                      |
| Short code lifetime                                            | Edge     | `ttl.AuthorizationCode` 60 seconds                                                                                                                                                | `providerConfig.ts`                    |
| Mix-up defence (RFC 9207, 9700 4.4)                            | Edge     | `iss` on every authorization response, advertised in discovery                                                                                                                    | `oauth21.test.ts`                      |
| Audience-restricted access tokens (9700 2.3, 4.10)             | Both     | Tokens for an API are RFC 9068 JWTs whose `aud` is the resource (RFC 8707); the API refuses to sign any other audience or scope                                                   | `resourceIndicators.test.ts`           |
| Client authentication without shared secrets (9700 2.5)        | Both     | `private_key_jwt` by default; shared secrets need an instance flag and a per-client opt-in, and are checked by the API; `client_secret_jwt` and HS\* algorithms are never offered | `clientAuthentication.test.ts`         |
| Token revocation visible to resource servers                   | Edge     | Introspection (RFC 7662) reads the API's store, including JWT access tokens, so a token whose session ended is inactive at once                                                   | `introspectionRevocation.test.ts`      |
| No open redirector (9700 4.11)                                 | Edge     | Errors are sent only to a registered redirect URI; an unregistered one gets an error page                                                                                         | `oauth21.test.ts`                      |
| Clickjacking (9700 4.16)                                       | Edge     | Hosted pages send `frame-ancestors 'none'`                                                                                                                                        | `hostedPages.test.ts`                  |
| CSRF on the authorization flow (9700 4.7)                      | Edge     | PKCE; interaction routes need same-origin `Sec-Fetch-Site` or `Origin`                                                                                                            | `authorizationCode.test.ts`            |
| No dynamic client registration                                 | Edge     | `features.registration` off; clients come only from the registry                                                                                                                  | `providerConfig.ts`                    |
| Step-up and freshness (`acr_values`, `max_age`)                | Edge     | Decided from the API's auth context, never the provider session's copy; an unmet requirement after step-up ends with `unmet_authentication_requirements`                          | `stepUp.test.ts`                       |
